# 📦 ECOUNT 재고 분석 대시보드

ECOUNT(이카운트) ERP의 재고·판매 데이터를 분석해 **어떤 재고가 잘 나가고, 어떤 재고가 묵고 있는지**를
한눈에 보여주는 웹 대시보드입니다.

| 탭 | 내용 |
|---|---|
| 종합 | KPI 요약, 월별 출고 추이, ABC 구성, **지금 살펴봐야 할 품목(추천 액션)** |
| 회전율 랭킹 | 잘 나가는 TOP 15 / 잘 안 나가는 TOP 15, 품목별 회전율·재고일수 |
| ABC 분석 | 파레토 차트, 매출 기여 기준 A/B/C 등급(효자품목 식별) |
| 체화·악성재고 | 일정 기간 출고가 없는 '죽은 재고' 목록과 묶여 있는 금액 |
| 판매 추세 | 월별 출고 추이, 상승/하락 추세 품목 |
| 발주 제안 | 안전재고·재주문점 기반 발주 필요 품목과 권장 발주량 |
| 품목 전체 | 전 품목 지표 통합 테이블, 검색·정렬·CSV 다운로드 |

## 빠른 시작 (데모 모드)

ECOUNT 인증키가 없어도 샘플 데이터로 바로 화면을 볼 수 있습니다.

```bash
pip install -r requirements.txt
python run.py
```

브라우저가 자동으로 열립니다(<http://localhost:8000>). 상단에 **「데모 데이터」** 배지가 표시됩니다.

## ECOUNT 실데이터 연동

### 1. API 인증키 발급

1. ECOUNT ERP 로그인 → **Self-Customizing → 정보관리 → API 인증키 발급**
2. 발급받은 **회사코드 / 사용자ID / 인증키**를 준비합니다.
   - 테스트 인증키를 발급받은 경우 테스트 서버(sboapi)로 접속해야 하며, 아래에서 `ECOUNT_TEST_SERVER=true`로 설정합니다.

### 2. 환경설정

```bash
cp .env.example .env
```

`.env` 파일을 열어 인증 정보를 입력합니다:

```ini
ECOUNT_COM_CODE=123456        # 회사코드
ECOUNT_USER_ID=admin          # 사용자ID
ECOUNT_API_CERT_KEY=xxxxxxxx  # API 인증키
```

### 3. 연결 확인 후 실행

```bash
python run.py
```

실행 후 <http://localhost:8000/api/test-connection> 에 접속하면
**Zone 조회 → 로그인 → 재고현황 조회** 3단계 진단 결과를 JSON으로 확인할 수 있습니다.

대시보드 상단의 **「⟳ 데이터 새로고침」** 버튼을 누르면 ECOUNT에서 최신 데이터를 다시 수집합니다.
(수집 결과는 `data/cache.json`에 저장되어 평소에는 API를 다시 호출하지 않습니다.)

### 조회 API 경로가 다른 경우

ECOUNT Open API의 조회 엔드포인트 경로·파라미터는 계정 설정/버전에 따라 다를 수 있습니다.
오류가 나면 ERP의 OpenAPI 가이드에서 실제 경로를 확인한 뒤
`app/ecount_client.py` 상단의 `ENDPOINTS` 딕셔너리만 수정하면 됩니다.

```python
ENDPOINTS = {
    "inventory_balance": "/OAPI/V2/InventoryBalance/GetListInventoryBalanceStatus",  # 재고현황
    "products":          "/OAPI/V2/InventoryBasic/GetBasicProductsList",             # 품목 목록
    "sales":             "/OAPI/V2/Sale/GetListSale",                                # 판매현황
    ...
}
```

응답 필드명이 다른 경우도 같은 파일의 `FIELD_CANDIDATES`에 후보 키를 추가하면 됩니다.

## 지표 설명 (경영 활용 가이드)

| 지표 | 계산식 | 보는 법 |
|---|---|---|
| **재고회전율** (연환산) | 기간 출고량 × (365÷기간일수) ÷ 평균재고 | 높을수록 잘 도는 재고. 업종 평균 대비 낮으면 과잉재고 의심 |
| **재고일수(DOI)** | 365 ÷ 회전율 | "현재 재고 수준이면 며칠치 장사인가" |
| **소진예상일** | 현재고 ÷ 최근 90일 일평균 출고 | 리드타임보다 짧으면 곧 품절 |
| **ABC 등급** | 출고금액 누적 80% → A, 95% → B, 나머지 C | A등급(소수 품목이 매출 대부분)은 품절 방지 최우선 관리 |
| **체화 등급** | 마지막 출고 후 경과일 (주의 60일↑ / 체화 90일↑ / 악성 180일↑) | 악성재고 금액만큼 현금이 묶여 있음 → 할인·처분 검토 |
| **판매 추세** | 최근 3개월 vs 직전 3개월 출고량, ±10% 기준 (진행 중인 달 제외) | 상승 품목은 재고 확충, 하락 품목은 입고 축소 |
| **안전재고** | z(서비스수준) × 일출고 표준편차 × √리드타임 | 수요 변동 대비 버퍼 |
| **재주문점(ROP)** | 일평균출고 × 리드타임 + 안전재고 | 현재고가 이 아래로 내려가면 발주 |
| **교차비율** | 회전율(금액) × 마진율 | 클수록 "잘 돌면서 이익도 남는" 품목. 낮으면 가격·재고 정책 재검토 |
| **재고자산 금액** | 현재고 × 입고단가 | 품목·등급별로 자금이 어디에 묶여 있는지 |

분석 파라미터(기간, 리드타임, 서비스수준, 체화 기준일 등)는 `.env`에서 조정합니다 — `.env.example`의 주석 참고.

## 프로젝트 구조

```
app/
  config.py         # 환경설정(.env) 로딩
  analysis.py       # 지표 계산 엔진 (순수 파이썬, 외부 의존성 없음)
  ecount_client.py  # ECOUNT Open API 클라이언트 (Zone→로그인→조회)
  providers.py      # 데모/실연동 데이터 공급 + 로컬 캐시
  demo_data.py      # 데모 샘플 데이터 생성기
  main.py           # FastAPI 서버
static/             # 대시보드 (HTML/CSS/JS, Chart.js)
tests/              # 분석 엔진 단위 테스트
run.py              # 실행 스크립트
```

## 테스트

```bash
python -m unittest discover tests -v
```

## 주의사항

- `.env`(인증키)와 `data/`(수집 데이터)는 git에 커밋되지 않습니다(.gitignore 처리).
- ECOUNT Open API는 호출량 제한이 있어 클라이언트가 호출 간격을 자동 조절합니다.
  데이터 새로고침은 필요할 때만 누르세요.
- 회전율의 평균재고는 현재고와 입출고 내역으로 월말 재고를 역산해 계산합니다.
  구매(입고) 조회 API를 쓸 수 없는 계정에서는 평균재고 정밀도가 다소 낮아질 수 있습니다.
